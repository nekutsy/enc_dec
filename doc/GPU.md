# GPU.md — Правила безопасности GPU

> ⚠️ Критично. Потеря GPU = эксперименты встают до физического вмешательства.

## Железо

- **Модель:** NVIDIA GeForce RTX 3070 Mobile, 8GB VRAM
- **Драйвер:** 590.48.01, CUDA 13.1
- **Torch:** 2.9.1+cu128

## Проблема ERR!

GPU склонен падать в состояние ERR! — `nvidia-smi` показывает `Fan/Temp/Perf = ERR!`. После этого:
- `torch.cuda.is_available() == False`
- `cuDeviceGetCount` возвращает 0
- Никакие программные методы сброса не работают

### Триггеры ERR!

1. Грубое завершение процесса с GPU (SIGKILL, краш)
2. Ошибка в процессе, держащем CUDA-контекст
3. Прерывание обучения без корректной синхронизации/очистки

### Восстановление

Единственный рабочий способ: `sudo reboot` (и тот может зависнуть — тогда только физический power-cycle). Физического доступа к машине нет → каждый ERR! это простой на неопределённое время.

## Правила

### При написании кода

1. **Всегда синхронизировать перед выходом:** `torch.cuda.synchronize()` + `torch.cuda.empty_cache()` перед любым `return`/`break`/`sys.exit()`
2. **Обработчики сигналов:** SIGINT/SIGTERM должны делать graceful cleanup (sync + empty_cache)
3. **Никаких SIGKILL** на процессах с GPU — только SIGINT/SIGTERM
4. **torch.compile(mode="default")** — не `reduce-overhead` (CUDA graphs повышают риск ERR при прерывании)
5. **Чекпоинты перед каждой потенциально опасной операцией** — потеря прогресса лучше, чем ERR

### При запуске обучения (уже встроено в код)

- `gpu_health_check()` — проверяет GPU ДО старта
- `cuda_safe_cleanup()` — зарегистрирован в atexit
- Mixed precision: `autocast(bfloat16)` без GradScaler (bfloat16 не требует скейлинга)
- TF32: включён по умолчанию (`use_tf32: true`)

### При инференсе

```bash
bin/enc-dec infer --gpu    # ок
```

Инференс не нагружает GPU как обучение, риск ERR ниже. Но если GPU уже в ERR — не поможет.

### При прерывании

- **Дать доработать текущий batch** — не CTRL+C в середине шага
- **Если нужно остановить:** один CTRL+C, подождать graceful shutdown
- **Не спамить CTRL+C** — это отправляет множественные SIGINT, повышая риск ERR
- **Никогда не `kill -9`** на Python-процессе с GPU

## На практике

Относиться к GPU как к хрупкому ресурсу. Лучше:
- Меньше batch size
- Больше чекпоинтов
- Осторожнее с `torch.compile`

…чем потерять GPU на дни.
